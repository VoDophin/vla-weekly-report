本周汇报：从多峰动作生成到 π 系列 VLA

日期：2026-10-22 建议汇报时长：20-25 分钟

汇报主线

本周围绕 π₀、π₀-FAST、π₀.₅ 和 RT-2，重点理解了五个相互关联的问题：

  1. 为什么 diffusion-style action expert 能表示多峰动作分布；
  2. π₀-FAST 怎样把连续动作块压缩成离散 token；
  3. π₀ 为什么被称为类似 MoE 的双专家模型；
  4. π₀ 的训练与推理怎样运行，以及 π₀.₅ 与 RT-2 的分层推理有何不同；
  5. Attention Survey 如何系统划分注意力机制，以及 π₀ 的 attention 应放在什么位置理解。

贯穿这五部分的一条主线是：VLA 不仅要理解图像和语言，还要选择合适的动作概率建模方式、动作表示以及模态间信息流。

一、Diffusion Action Expert 为什么具有多峰性？

术语上，π₀ 的 action expert 使用的是 Flow Matching，不是经典 DDPM 去噪网络；本部分把二者放在 diffusion-style 概率生成策略的共同背景下讨论。两者的具体训练目标不同，但“从简单噪声分布逐步生成条件动作分布”的多峰性逻辑相通。

1. 什么是多峰性？它与概率函数的“多个峰”有什么关系？

这里的“多峰”是 multimodal distribution，不是“图像、语言、动作等多模态输入”。

固定当前观察和任务条件 c=(图像, 指令, 机器人状态) 后，机器人未来动作仍可能不唯一。例如绕开障碍时可以从左边绕，也可以从右边绕；抓取同一物体时也可能存在不同但都有效的抓取姿态。于是条件动作分布 p(A|c) 中会有多个高概率区域。

  • 一维概率密度曲线上，多个模式通常表现为多个局部峰值。
  • 在高维动作块中，一个“峰”更准确地说是一个高概率区域，代表一类相近的完整动作轨迹。
  • 多峰性应观察联合动作块分布，而不只是某一个关节或某一个时刻的边缘分布。

例如：

动作方案 1：从障碍左侧绕行  ┐
                           ├→ 同一条件下的两个高概率区域
动作方案 2：从障碍右侧绕行  ┘

若使用普通的确定性 MSE 回归，模型在同一条件下只能输出一个点。其最优解是条件均值 E[A|c]。当左绕和右绕都存在时，这个均值可能位于两条路线中间，反而撞向障碍。

因此，多峰建模的目标不是“一次同时执行多个动作”，而是：模型保留多个合理方案，每次采样得到其中一个完整、可执行的方案。

2. 只增加一个噪声输入，就能实现多峰性吗？

不能。噪声是产生不同样本的必要入口之一，但不是多峰性的充分条件。

π₀ 的生成过程可写成：

固定条件 c + 初始噪声 ε
        ↓
时间相关向量场 vθ(Aτ, τ, c)
        ↓ 多次 Euler 更新
最终动作块 A

在 π₀ 使用的确定性 ODE 求解中：

  • 条件相同、初始噪声相同、数值求解过程相同，输出就相同；
  • 条件相同但初始噪声不同，才可能得到不同动作方案；
  • 但前提是训练出的映射确实把不同噪声区域输送到目标分布的不同模式。

如果只是把独立噪声 z 拼到普通回归模型中，再训练

L = ||f(c,z)-A||²，

而训练数据没有规定 z 与动作方案的稳定对应关系，那么给定任意 z，模型面对的目标分布仍然是 p(A|c)。MSE 的最优解仍是 E[A|c]，模型完全可以忽略噪声。

所以关键不在“有没有随机输入”，而在 训练目标是否让噪声参与一个正确的分布变换。Flow Matching 的做法是：

  1. 从数据中取真实动作块 A；
  2. 采样高斯噪声 ε 和流时间 τ；
  3. 构造中间状态 Aτ = τA + (1-τ)ε；
  4. 学习当前位置的速度 A-ε；
  5. 推理时从噪声出发，沿学到的时间相关向量场积分到动作分布。

对中间时刻 0<τ<1，当前状态 Aτ 同时含有噪声和部分动作信息。不同位置对应的后验动作分布不同，因此局部平均方向也不同。不同初始噪声经过连续的局部修正，便可能进入不同的动作模式。

可以把它理解成：

τ=0：       ● ● ● ● ● ●       高斯噪声
             ↙  ↓  ↘
中间：      ●●       ●●        当前位置逐渐携带“属于哪类动作”的信息
τ=1：     左绕模式   右绕模式

多峰结构来自训练数据中的多个合理方案；噪声负责在这些方案之间进行采样；向量场负责把噪声正确地变换成目标动作分布。

3. 只有一个时间步的 diffusion model 是否具有多峰性？

需要区分三种“一个时间步”。

情况是否可行关键解释
每条训练样本只随机抽一个 τ可以，π₀本来就是这样训练不同 batch 抽到不同 τ，共享网络最终覆盖整条连续路径
训练时永远只看一个固定噪声等级或只看端点通常不足缺少中间状态上的速度监督，不能可靠学到怎样分流到多个模式
推理时从纯噪声只更新一步理论上可以，标准模型通常不行必须专门学习或蒸馏一个准确的一步 transport map；普通 Flow Matching 的一步大步长更新容易产生较大误差

以左右动作 A=-1 和 A=+1 各占一半为例。在纯噪声端 τ=0，输入噪声与目标动作独立，MSE 的理想速度是 E[A|c]-ε=-ε。如果直接用步长 1 更新一次，就得到 ε-ε=0，正好落在两个模式之间。

因此，标准 diffusion/Flow Matching 的多步过程不是为了“每一步再随机一次”，而是为了让模型不断依据新的当前位置重新判断局部方向。前一步到达的位置包含了更多模式信息，下一步的条件平均就不再是对所有动作方案做同一个全局平均。

准确结论是：一步生成器在表示能力上可以多峰，但“输入噪声 + 一步 MSE 回归”不会自动学会正确多峰分布。 一步 diffusion、consistency model 或蒸馏方法需要专门的训练设计。π₀采用约 10 次 Euler 更新，是生成质量与实时控制成本之间的折中。

本部分结论

Diffusion-style action expert 的多峰性来自“随机初始样本 + 学到的分布输运”，不是来自噪声本身。固定噪声时输出可复现；改变噪声时只有在模型学会正确 transport 的前提下，才会得到目标分布中的不同合理动作。

二、π₀-FAST 的离散化算法

1. 为什么要使用压缩式离散化？

早期 VLA 常把每个时刻、每个动作维度分别分箱。例如长度为 H、动作维度为 D 的动作块，需要约 H×D 个动作 token。

这种方法容易接入 VLM 的 next-token 接口，但在高频控制中有三个问题：

  1. 序列过长。 控制频率越高、动作块越长，token 数按采样点数线性增长。
  2. 信息高度重复。 相邻时刻动作通常非常接近，模型反复预测相似 token。
  3. 训练信号低效。 teacher forcing 下，“复制前一个 token”就能命中很多位置，模型可能依赖局部重复，而没有充分学习由图像和指令决定的整体轨迹。

动作采样点很多，不等于动作本身很复杂。同一条平滑抬手轨迹采成 10 点或 100 点，底层运动形状没有增加 10 倍复杂度。FAST 的目标是让 token 数更接近 轨迹本身的信息复杂度，而不是机械地跟随采样频率增长。

2. FAST 算法流程

FAST 把整个动作块当作时间序列压缩，而不是逐时刻独立分箱：

连续动作块 A∈R^(H×D)
→ 分位数归一化
→ 每个动作维度沿时间轴做 DCT
→ 系数缩放并四舍五入
→ 按低频优先展开整数系数
→ BPE 合并常见整数片段
→ FAST 动作 token

步骤一：分位数归一化

对每个动作维度分别统计训练集第 1 和第 99 百分位数，并大致映射到 [-1,1]。这样可以统一不同关节、夹爪或机器人动作维度的数值尺度，并降低极端离群值对缩放的影响。

步骤二：沿时间轴做 DCT

对每个动作维度的整段时间序列独立做离散余弦变换。低频系数描述平均水平和缓慢变化，高频系数描述快速变化与细节。

平滑动作通常把大部分信息集中在少量低频系数中。需要强调：DCT 本身是可逆变换，不减少系数数量，也不产生信息损失。

步骤三：缩放与量化

对 DCT 系数 c 计算 q=round(γc)。许多较小系数会被量化成 0，使整数系数序列更稀疏、更容易压缩。

  • γ 较大：保留更细精度，但通常更难压缩；
  • γ 较小：产生更多 0 和重复片段，但重建误差更大。

FAST 的主要有损误差来自这一步，而不是 BPE。

步骤四：低频优先展开

先放所有动作维度的最低频系数，再放所有维度的下一频率系数。这样最重要的整体轨迹信息出现在序列前部，也让不同动作维度的同一频率成分靠在一起。

步骤五：BPE 压缩

BPE 在训练动作语料上反复合并常见的相邻整数片段，例如连续的 0 或常见系数组合。一个 BPE token 可以代表多个量化系数，因此最终序列明显缩短。

BPE 对量化后的整数序列是无损的：解码时可以完整展开回原整数序列。动作重建流程为：

FAST token
→ BPE 解码
→ 量化系数矩阵
→ 除以 γ
→ 逆 DCT
→ 撤销归一化
→ 连续动作块

压缩率与动作精度怎样权衡？

FAST 的核心权衡是：token 越短，训练和自回归推理越省；但量化过强会损失细粒度动作。真正引入重建误差的是 DCT 系数量化，BPE 只是无损地缩短量化后的整数序列。

量化尺度 γ 控制这一权衡。由 q=round(γc) 可知，解码后的系数量化步长是 1/γ：

设置系数表现token 序列可能影响
较小 γ，量化较粗更多小系数变成 0，重复片段增多通常更短、更易被 BPE 压缩轨迹细节、高频转折和接触动作可能失真
较大 γ，量化较细保留更多非零系数和数值差异通常更长重建更准确，但训练冗余和串行推理成本上升

高频系数并不会被 FAST 固定删除；只是它们在平滑动作中往往较小，因此更容易在粗量化时变成 0。对大范围移动来说，这些误差可能影响不大；但在插入、接触、夹爪闭合或快速转向等动作中，小幅高频变化可能决定任务能否成功。

因此，不能只用“平均 token 数最少”选择压缩强度。至少要同时观察：

  1. 动作块的数值重建误差；
  2. 速度、加速度和时间连续性是否被破坏；
  3. 关键接触阶段是否保留；
  4. VLA 的真实机器人任务成功率；
  5. token 长度带来的训练吞吐和自回归延迟。

数值重建误差与任务性能也不完全等价：有些关节的微小误差无关紧要，夹爪时机或末端姿态的同等误差却可能导致失败。最终应选择任务成功率、动作精度与计算成本之间的折中点，而不是单独追求最高压缩率。

Tokenizer 与 VLA 是两个训练阶段

先在动作语料上学习 BPE 词表和合并规则，再用固定 tokenizer 把 VLA 的监督动作编码成 token。VLA 训练时学习的是“给定图像、指令和状态，预测哪些 FAST token”，不是同时重新学习 DCT。

3. 为什么离散化方式训练快、推理慢，而 diffusion 训练慢、推理快？

这里的“快慢”是 π₀-FAST 与 π₀ 在论文设置下的相对结果，不能推广成所有离散模型和所有生成模型的普遍规律。

π₀-FAST 为什么训练较快？

  • 训练时完整正确 token 序列已知，可用 teacher forcing 在一次前向中并行计算所有位置的 next-token 损失；训练不是逐 token 串行。
  • FAST 把冗长、重复的动作值变成更短、信息更集中的序列，提高了监督效率。
  • next-token 交叉熵与预训练 VLM 的接口一致，容易复用已有优化与混合训练流程。
  • FAST 论文报告：达到相近评测表现时，π₀-FAST 使用的 GPU 小时约为 π₀ Flow Matching 模型的五分之一。这个数字是具体实验结果，不是算法定律。

π₀-FAST 为什么推理较慢？

自回归生成时，第 i+1 个 token 必须等待第 i 个 token 生成，因此几十个 FAST token 仍需顺序解码。训练时可并行，是因为正确前缀已知；推理时未知未来 token，所以不能同样并行。

π₀ 的 Flow Matching 在每个积分步中会同时处理整个 50 步动作块。虽然需要约 10 次 action expert 调用，但动作块内部不是逐动作 token 串行生成。于是，在该设置下：

π₀-FAST：较少训练 GPU 小时；推理需串行生成约几十个 token
π₀：     训练收敛较慢；推理用约 10 个并行整块更新

还要避免一个误区：π₀训练每条样本只抽一个 τ，不会在一次训练迭代中完整运行 10 次去噪。训练较慢主要是论文观察到的端到端收敛差异，不能简单解释为“训练时做了 10 步 diffusion”。

本部分结论

FAST 的核心不是“把连续值变成整数”，而是先利用动作轨迹的时间结构压缩，再离散化。它用较短 token 序列换取高效 next-token 训练，但自回归串行生成仍会增加控制延迟。

三、π₀ 的 MoE 结构

1. MoE 的经典定义与应用

经典 Mixture of Experts 包含三部分：

  1. 多个结构相同或相近的 expert；
  2. 一个 router/gating network，根据当前 token 的表示计算路由权重；
  3. 将 token 发送给 Top-k expert，再合并 expert 输出。

现代稀疏 MoE 常把 Transformer 的 FFN 子层替换为多 expert 版本。每个 token 只激活少数 expert，因此可以显著增加总参数容量，而单次计算量不按 expert 总数同比增长。训练时通常还要加入负载均衡约束，避免所有 token 都挤到少数 expert。

经典应用包括：

  • 大语言模型：不同 token 或语义模式由不同 FFN expert 处理；
  • 多任务学习：不同任务共享部分模型，同时路由到不同专家；
  • 多模态或多领域模型：让不同数据类型或领域获得专门参数。

MoE 与模型集成不同：模型集成通常运行多个完整模型再平均结果；稀疏 MoE 在单个网络内部只激活少量 expert，并进行联合训练。

2. π₀ 的双专家结构

π₀论文称其结构 analogous to a mixture of experts with two mixture elements。它与经典稀疏 MoE 相似，但不是标准形式。

对比项经典稀疏 MoEπ₀
expert 数量通常很多两套专家权重
路由方式学习式 router，常用 Top-k按 token 类型固定路由
expert 位置常见于 FFN 子层两套参数贯穿 Transformer 层
负载均衡通常需要不需要学习负载均衡
expert 间交流合并路由后的输出在共同 attention 计算中交换信息

π₀的两条参数路径是：

  • VLM expert： 由约 3B 参数的 PaliGemma 初始化，处理图像和语言 token，保留互联网图文预训练获得的语义能力；
  • action expert： 约 300M 参数，从随机初始化开始，处理机器人状态、带噪动作和 flow time，学习连续控制与动作块协调。

它们不是两个完全独立的模型。每一层中，两侧分别使用自己的 RMSNorm、Q/K/V 投影、attention 输出投影和 FFN 参数；随后两侧产生的 Q/K/V 进入同一次受 mask 控制的 attention，使动作 token 能读取图像、语言和状态信息。

可以概括为：

图像、语言 token ─→ VLM expert 参数 ┐
                                      ├→ 共同的受 mask attention → 各自后续参数
状态、动作 token ─→ action expert 参数┘

这种设计有三个目的：

  1. 让 VLM 保留视觉语言专业能力；
  2. 让 action expert 专门适应连续动作、噪声输入与 Flow Matching 目标；
  3. action expert 较小，推理时重复运行约 10 个积分步的成本更低。

因此，更准确的名称是 固定模态路由的双专家 Transformer。它借用了 MoE 的“参数专业化”思想，但没有经典 MoE 的学习式 router、Top-k 路由与大量 FFN experts。

四、π₀ 的训练与推理流程

1. π₀ 的训练流程

模型初始化

  1. 图像和语言侧加载预训练 PaliGemma；
  2. 新增机器人状态投影、动作与时间输入 MLP、action expert 和速度输出头；
  3. action expert 等机器人专用模块从随机参数开始；
  4. 使用多任务、多机器人示范数据继续训练完整 π₀ 系统，之后可再用目标任务数据 post-training。

一条样本怎样产生训练损失？

从示范数据中取：

  • 当前多相机图像和语言指令；
  • 当前机器人状态 q_t；
  • 未来真实动作块 A_t=[a_t,...,a_(t+H-1)]，π₀中 H=50。

然后执行：

  1. 采样高斯噪声 ε 和流时间 τ；
  2. 构造带噪动作 A_t^τ=τA_t+(1-τ)ε；
  3. 图像和语言经过 VLM expert；状态与带噪动作经过 action expert；
  4. 用 block-wise causal attention 让动作读取图像、语言、状态和整段动作块；
  5. 从 50 个动作位置输出速度场 v_θ(A_t^τ,τ,o_t)；
  6. 用 MSE 逼近目标速度 A_t-ε；
  7. 反向传播，更新所有允许训练的参数。

核心损失为：

L = ||v_θ(A_t^τ,τ,o_t)-(A_t-ε)||²。

训练时每条样本只随机抽一个 τ。同一示范在不同训练轮次再次出现时，会重新抽噪声和时间，从而为同一动作路径提供不同位置的局部速度监督。

Block-wise causal attention：谁能读取谁？

令 B₁=[图像,语言]、B₂=[机器人状态]、B₃=[50个带噪动作位置]：

当前更新的块可以读取 B₁可以读取 B₂可以读取 B₃
B₁ 图像/语言是否否
B₂ 状态是是否
B₃ 动作是是是

这里的“causal”发生在块之间：只能读自己和前面的块。块内部是双向的，所以 50 个未来动作位置可以彼此读取并联合协调；它们不是按控制时刻逐个自回归生成。

2. π₀ 的推理流程

推理时没有真实动作，流程如下：

当前图像 + 指令 + 机器人状态
              ↓
固定观察条件，采样 50×D 的高斯噪声动作块 A^0
              ↓
[action expert 预测速度 → Euler 更新] × 10
              ↓
得到连续动作块 A^1
              ↓
执行动作块前一部分
              ↓
重新观察环境并再次规划

Euler 更新为 A^(τ+δ)=A^τ+δv_θ(A^τ,τ,o)。π₀使用约 10 步、δ≈0.1。

模型一次生成未来 50 个控制时刻的动作，但机器人通常只执行其中一部分，然后重新观察。论文设置中，不同平台每次执行前 16 或 25 步。这样形成“块内短期开环、块间重新闭环规划”的控制方式。

Action Chunking：为什么预测较长，却只执行前一部分？

需要区分两个长度：

  • 预测/规划长度 H：模型一次联合生成多少个未来动作；
  • 执行长度 K：在重新观察前，机器人实际执行其中多少步，且 K<H。

不把整段 50 步全部执行完，是因为预测基于生成动作块时的那一帧观察。真实执行中会出现控制误差、物体滑动、接触碰撞、相机变化以及其他环境扰动，实际轨迹会逐渐偏离预测轨迹。若始终执行到块尾，模型在较长时间内都不能利用新观察纠偏；只执行前缀后重新规划，可以及时把真实状态反馈给策略。

那么，为什么不直接把 chunk size 缩短到 K，每次生成一小段并全部执行？原因是 规划视野和控制视野承担不同作用：

  1. 较长动作块让模型联合考虑动作的前后依赖，例如“接近 → 对准 → 闭合夹爪 → 抬起”。前段动作可以为了后段目标提前调整姿态，而不是只追求眼前一步最容易完成。
  2. π₀ 的动作块内部使用双向 attention。较早动作位置能与较晚动作位置共同形成一致计划，因此生成的前缀通常会受到整段任务阶段结构的约束。
  3. chunk 过短会减少这种时间上下文，并要求更频繁地运行 VLM 和 action expert，增加计算开销与控制延迟；相邻短块还可能各自合理但衔接不一致。

这里的“后段信息帮助前段”不是说模型提前看到了真实未来轨迹。后段动作同样是模型生成的候选计划；价值在于整段动作通过联合建模相互约束。较长 H 也不是越长越好：过长会增加生成难度，远端预测更不可靠。系统最终采用的是滚动时域折中：用较长 H 获得连贯规划，用较短 K 保持反馈纠偏。

图像、语言和状态前缀在 10 次积分中不变，因此可以缓存其 attention key/value；每一步主要重算动作 suffix，降低重复计算成本。

3. π₀.₅ 与 RT-2 多层推理结构的差异

π₀.₅ 将策略分解为：

π(a, l_hat | o,l)=π(a|o,l_hat) · π(l_hat|o,l)。

也就是先预测高层子任务文字 l_hat，再以该子任务为条件生成低层连续动作块。

RT-2 基础版本把观察和指令直接映射成离散动作 token。RT-2-CoT 更接近分层推理：先在同一条自回归序列中输出自然语言计划，再继续输出离散动作 token。

π₀.₅ 的区别是：高层仍由 VLM 自回归生成文字，但低层不再继续沿语言词表逐 token 输出动作，而是调用专门的连续 action expert，用约 10 步 Flow Matching 生成动作块。一个高层子任务可以持续多个低层控制周期，因此两层不仅输出形式不同，更新频率也不同。

一句话比较：π₀.₅ 在“先想做什么、再决定怎么动”的逻辑上接近 RT-2-CoT，在低层动作生成方式上继承 π₀。

五、Attention 的主要类别

本部分依据 Brauwers 与 Frasincar 的综述 *A General Survey on Attention Mechanisms in Deep Learning*。该综述不把 attention 简单列成一组互斥名称，而是提出三个彼此正交的分类维度。同一个 attention 模块可以同时属于多个类别。

1. Attention 的统一计算框架

一般 attention 模块包含四步：

  1. 从输入特征得到 keys K 和 values V；
  2. 用 query q 与每个 key 计算 score；
  3. 通过 alignment 把 score 变成 attention weights；
  4. 对 values 加权求和，得到 context vector。
query q + keys K
        ↓ score
attention scores e
        ↓ alignment
attention weights a
        ↓ 对 values V 加权
context vector c

因此，各种 attention 的差异可以来自：输入特征怎样组织、score/alignment 怎样定义、query 从哪里来、一次使用多少 query。

2. Feature-related attention：按被读取特征的结构分类

这一大类回答：被 attention 读取的特征是什么结构？

子维度主要类别含义
特征数量 multiplicitysingular features只对一组特征做 attention
coarse-grained co-attention用一个输入的压缩表示去查询另一个输入
fine-grained co-attention一个输入的全部特征分别与另一个输入交互
multi-grained / rotatory组合粗细粒度，或让多组输入轮流作为彼此查询
特征层级 levelssingle-level只在一个粒度上做 attention
attention-via-attention一层 attention 的结果参与另一层 attention
hierarchical attention从低层到高层逐级汇总，例如词→句子→文档
特征表示 representationssingle-representational每个对象只有一种特征表示
multi-representational对同一对象的多种表示加权融合成 meta-representation

例如图文问答同时有图像特征和问题特征，适合用 co-attention 理解；文档分类同时有词级和句级结构，适合用 hierarchical attention 理解。

3. General attention：按 attention 内部运算分类

这一大类回答：相似度怎么算、注意力范围怎样选、权重作用到什么粒度？

Scoring：query 与 key 怎样打分？

  • additive/concatenate scoring：用小网络组合 query 和 key；
  • multiplicative/dot-product scoring：直接做点积；
  • scaled multiplicative scoring：点积再除以 sqrt(d_k)，Transformer 采用此形式；
  • general、biased general、activated general：在点积前后加入可学习矩阵、偏置或激活；
  • similarity scoring：使用余弦相似度、欧氏距离等显式相似度。

缩放点积的原因是：维度较大时，点积幅值容易过大，使 softmax 饱和、梯度变小；除以 sqrt(d_k) 可稳定数值尺度。

Alignment：哪些位置真正参与？

  • global/soft attention：所有允许位置都获得连续权重；
  • hard attention：只采样或选择一个位置，通常难以直接使用普通反向传播；
  • local attention：只在一个局部窗口内做 soft attention；
  • reinforced attention：用强化学习选择一个子集，再在子集内做 soft attention。

Dimensionality：一个 value 使用几个权重？

  • single-dimensional attention：每个 value 向量只有一个标量权重；
  • multi-dimensional attention：value 向量的不同特征维度可以有不同权重。

4. Query-related attention：按 query 的来源和数量分类

这一大类回答：是谁在提出问题，一次提出几个问题？

Query type

  • basic query：来自当前解码器状态、辅助变量等直接上下文；
  • specialized query：来自另一 attention 模块的 context、另一组输入的平均表示等；
  • self-attentive query：query、key、value 都由同一组特征产生，用来建模序列内部位置之间的关系。

Self-attention 中，每个位置都可以提出 query，并从其他位置读取与自己相关的信息。文字中可建模代词与名词、动词与主语的关系；图像中可建模不同区域之间的关系。

Query multiplicity

  • singular-query attention：一次预测使用一个 query；
  • multi-head attention：多个投影后的 query/K/V 并行工作，从不同表示子空间读取信息；
  • multi-hop attention：多轮串行 attention，上一轮结果参与下一轮查询；
  • capsule-based attention：使用 capsule 结构组织多组查询与表示。

Multi-head 与 multi-hop 的区别是：multi-head 主要是并行的多个视角，multi-hop 主要是串行的多轮读取。

5. 常见名称不是互斥分类

一个 Transformer attention 可以同时是：

  • self-attention：Q/K/V 来自同一序列；
  • multi-head：并行使用多个 attention head；
  • scaled multiplicative：使用缩放点积打分；
  • soft/global：对 mask 允许的所有位置做 softmax 加权；
  • single-dimensional：每个 head 对每个 value 位置给一个标量权重。

因此，“self-attention、soft attention、multi-head attention”不是三选一，而是从不同维度描述同一个模块。

6. π₀ 的 attention 放在这套分类中的位置

π₀主要使用 Transformer 式 multi-head self-attention，并采用缩放点积与 softmax。它的特殊之处不在于发明新的 score 函数，而在于：

  1. 不同 token 类型走不同 expert 参数；
  2. block-wise causal mask 规定了哪些 query 可以读取哪些 key/value；
  3. 动作块内部双向可见，但块与块之间遵守单向信息流。

普通 token-level causal attention 的规则是：位置 i 只能读取 j≤i 的位置。π₀的 block-wise causal attention 则是：

图像/语言块：只读图像/语言块
状态块：    读图像/语言块 + 状态块
动作块：    读图像/语言块 + 状态块 + 整个动作块

所以 50 个动作位置虽然对应未来不同机器人时刻，却处于同一个动作块中，可以彼此双向读取。这里的“future blocks”指序列中排在右侧的块，不等于动作块内较晚的机器人控制时刻。

在 Attention Survey 的三轴体系中，causal/block-wise causal 更适合作为 可见性与信息流约束 来理解，而不是把它当作与 self-attention、multi-head 并列且互斥的第四大类。

本部分结论

Attention 的名称来自不同分类轴：feature-related 描述读什么，general 描述怎么算，query-related 描述谁来问、问几次。π₀使用的是 Transformer 式 multi-head self-attention，再用双专家参数和 block-wise causal mask 约束模态专业化与信息流。

总结

本周内容可以压缩成五句话：

  1. 多峰性描述的是同一观察条件下存在多个高概率动作方案；噪声提供采样差异，学到的分布输运才负责形成正确模式。
  2. FAST先用 DCT 利用轨迹的时间结构，再量化并用 BPE 压缩，使动作 token 数接近信号复杂度，而不是采样点数量。
  3. π₀ 的 MoE是固定模态路由的双专家结构：VLM expert 保留语义能力，action expert 专门学习连续控制，二者通过 attention 交换信息。
  4. π₀ 的 Flow Matching训练时随机学习一个路径位置的速度，推理时从噪声出发多步积分；π₀.₅ 进一步加入“高层文字子任务 → 低层连续动作”的两级推理。
  5. Attention应按多个正交维度理解；π₀的关键组合是 multi-head self-attention、缩放点积、softmax，以及规定“谁能读取谁”的 block-wise causal mask。
